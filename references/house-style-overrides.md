# 本机三栏目体例 × lieflat 白名单：覆盖决策与实测基线

2026-09-19 首用于 09-19 三篇成稿（对谈 019 / 拆解 013 / 热点 010），后续每期成稿沿用本决策，除非用户改口径。

## QA 顺序（管线固定三步）

1. lieflat 结构清理 → 产出 **v2，绝不覆盖 v1**（cp v1 v2 后 patch，diff 核对改动行数与预期一致）
2. check-ai-isms.sh 禁词兜底
3. **破折号清零**（2026-10-09 新增）：正文「——」按语义分流改写（插入解释→句号/括号、并列强调→冒号、列举→逗号），全篇保留 ≤3 处；密度超 2/千字判命中。依据：文档 API 检测器对破折号密度权重最高（人工参照 0.00/千字 vs 本账号过白名单后成稿实测 6-9/千字、19-31 处/篇，仍被判 90% AI；清零后句长σ/句首多样性/虚词密度已全部优于人工基线）。栏目固定体例行的破折号不计入
4. 验收：v1/v2 字数应基本持平（删减性微调，±1% 以内）；diff 行数 = 修改处数 × 2

## 覆盖优先级（冲突时从上到下）

1. **风格文档（栏目体例）> 本 skill 规则**：拆解栏目六段式「一~六」序数小标题是固定体例（往期每期稳定出现 = 编辑设计而非 AI 漂移），规则 6 不剥编号。同理对谈栏目头「主持人：拾闻（AI）｜嘉宾：永亮」等固定文案不动。
2. **对话体豁免**：拾闻对谈 Q&A 口播段不按规则统一改写——翻案腔、顿号对举、「恰恰」「正是」等口播高频词保留；只处理叙述段（开场/技术纵深/信息来源）。
3. **技术/事实清单豁免**：顿号罗列若属完整枚举（三值集合、GitHub 仓库名录、人名、厂商名单、代码分支）不动——「材料必须完整列出」条款；人名一律不删不改。
4. **总说+分说冒号保留**：「按六件事拆：X、Y、Z」「适合的人很清楚：…」「官方口径一句话：…」（带归因功能的不是提示语）。
5. **提示语引出删除（规则 5）**：「这期的主线：」「一句话说清：」「一句话评价：」「提醒一句：」→ 直接删提示语让正文接上，信息不丢；承接上文的过渡提示语（「回到本期主线」）保留、只把冒号换句号。
6. **揭晓式破折号改句号**：「它的答案是不——工具调用…」→「它的答案是否定的。工具调用…」（规则 4）；解释性破折号（「摘要有损——文件路径…」）保留。
7. **翻案腔只改固定句式**：仅当「不是…而是…」模板化使用且文章没走过误解→修正过程时改写为正面直陈；文章确实走了修正过程的保留（规则 1 允许写作者自我修正）。对举式否定（「判断依据不是一段文字，而是两个概率」）是事实二选一，非翻案腔，不动。
8. **翻译腔触发线是同段五条以上**：单条标记零星分布（0.1-1.2/千字）不构成触发，不动。

## 脚本用法坑

- `check-translationese.py` 参数是**目录不是单文件**，传文件报「找不到语料」；会连目录下 v1/meta 一起扫，按输出表的每千字列定位单篇读数。

## 实测基线（09-19 三篇 v2，2 万汉字）

- 破折号 4.8-7.6/千字（脚本基准线 5.02，人写语料 4.57 左右）——技术文破折号密度高是体例使然，**别看到密度高就批量删**，只处理揭晓式用法
- 提示性冒号 ≤0.9/千字、段首序数词 ≤1.0/千字（阈值内）
- 「不是…而是」改写后归零（热点篇 0.51→0.00）
- **修改量预期：5000 字成稿约 2-3 处**；三篇共 7 处是正常产出——白名单纪律优先于修改数量，没命中就逐字保留，不为凑修改量扩大解释范围
